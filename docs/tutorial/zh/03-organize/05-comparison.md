# 3.5 Group、Layer 与 Gather：结构、顺序与选择

三者回答不同的问题：Group 定义空间组合，Layer 定义覆盖顺序，Gather 选择已有单位执行命令。
它们不是三种可以相互替换的容器。

| | Group | Layer | Gather |
|---|---|---|---|
| 职责 | 局部结构与整体放置 | 由下到上的覆盖顺序 | 共同执行命令 |
| 同一实例可归属 | 一个直接父 Group | 最外层单位的一个有效 Layer | 多个 Gather |
| 空间变换 | 变换整个组合 | 没有 | 对所有选中单位执行命令 |
| 保持的关系 | 局部坐标与继承默认属性 | 覆盖顺序 | 只有成员关系，没有空间约束 |
| 嵌套 | 允许 | 本阶段没有图层组 | 扁平，加入其他 Gather 时展开成员 |
| 能否直接 draw | 可以 | 不可以 | 不可以 |

1. g1 上移，A 与 B 一起移动，C 不动。因此即使没有操作 g2，g2 内 B 与 C 的相对位置也已经改变。
2. g2 右移，B 与 C 一起移动，A 不动。因此 g1 内 A 与 B 的相对位置也改变。B 接受了两次命令，各一次。

**Gather 保留的是成员关系，不是局部坐标关系。** 它没有父变换或约束，
不会在共享成员被另一个集合操作时，自动带动本集合的其余成员。

这并不意味着一次 Gather 变换会随意打乱成员：同一条命令对所有当前目标应用同一个世界空间仿射变换。
平移保持间距，旋转和缩放使用共同指定的中心。它不保证这些关系在其他重叠集合的后续操作下保持稳定。

同一次命令中的重复目标只处理一次；两次独立命令中的共享目标会按调用顺序分别接受变换。
Gather 不保留嵌套关系，`Gather(g1, g2)` 得到的是当前成员身份的扁平并集。

## Group 保留组合的局部结构

Group 保存局部坐标结构。对 Group 做变换时，所有部分通过同一个父级放置一起变换。
Group 可以嵌套，但每个实例只有一个直接父 Group。

Gather 将最外层 Group 视为操作单位。尝试选择组内某个部分时，会提升为最外层 Group 并提示。
这样，重叠 Gather 不会意外地只移动组合中的一个零件。

Group 不是不可变对象，也不是刚体约束：显式编辑、添加或移除成员仍然可以改变内部排列。
这里保证的是“操作整个 Group 时保留成员的局部放置”，而不是“任何编辑都不能改变成员间距”。

## Layer 独立管理覆盖顺序

Layer 没有几何变换。它可以容纳独立实例或整个 Group，而 Gather 可以跨多个 Layer 选择操作单位。
最外层 Group 整体位于一个 Layer。

[三明治案例](04-layers.md)展示了区别：
Gather 可以让底板和盖板一起移动，中间的独立物件仍夹在两层之间。
改为 Group 后，整个组合提升到最高成员层，外部物件不再能穿插到成员之间。

`layer.to_gather()` 捕获该层当前的顶层成员，以便共同操作。
它不会让 Layer 拥有空间变换，也不会持续同步后续的图层成员增删。

## 如何选择

- 主体、端口和标签应当保持为一个组件：Group。
- 临时共同移动或修改几个独立单位：Gather。
- 同一批实例存在多种互相重叠的操作选择：多个 Gather。
- 控制谁覆盖谁：Layer。

对象编辑影响后续 draw 捕获，已有 Canvas 记录不会追随 Group 或 Gather 的后续操作。
调整 Layer 身份的层序，则会改变已分配到这些层的记录之间的覆盖顺序。

试试先操作 g2 再操作 g1：两次平移的最终位置相同，但中间状态不同。
再将其中一次平移改为绕原点旋转，观察一般变换为何依赖调用顺序。
